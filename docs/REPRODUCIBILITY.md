# Reproducibility

## What can be done from this checkout?

There are three distinct scopes. Completing a narrower one does not imply that a broader experiment has been rerun.

| Scope | Included inputs | What it establishes |
|---|---|---|
| Synthetic dry run and the cited tests | Tiny generated tensors and models | The training, objective, and evaluation code runs end to end on a controlled case; the trunk stays frozen in the A2 and A3 probes. The quantizers are not exercised by either |
| Selected tables and the figures from curated result files | `paper/artifacts/` and its manifest | The values of the tables listed under "Tables and figures" and the three figures follow from the shipped result files |
| Raw experimental replay | Original checkpoints, raw split files, environment records, datasets | Not available from this checkout alone |

`tests/` holds the two test files that the paper cites for the frozen-trunk behavior of the A2 and A3 probes. The other unit tests, and the tools that checked the manuscript against the result files during development, are not part of this repository.

## Installation

Use Python 3.12 in a new virtual environment. From the repository root:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements/tested.txt
python -m pip install -e '.[dev]'
```

`requirements/tested.txt` lists the direct dependencies of the environment in which the dry run, the tests, and the table generators were run for this release (Python 3.12.13). It is not the original training freeze and not a transitive, platform-independent lock. The historical environment listings in `paper/artifacts/env/` are **evidence records, not installation requirements**. They can contain redacted entries, historical CUDA packages, and packages unrelated to the released implementation. Do not install them with `pip install -r`.

The implementation does not require the private VCS dependency named in the original environment record. Different PyTorch builds may be needed on other platforms. Changes to package versions are not evidence of bit-exact agreement with the historical measurements.

## Dry run and tests

```bash
CUDA_VISIBLE_DEVICES='' python scripts/phase1_dry_run.py
CUDA_VISIBLE_DEVICES='' python -m pytest -q
```

The dry run constructs a tiny model and synthetic data. The tests train the A2 and A3 probes on tiny models and assert that no trunk parameter changes and that captured keys and values carry no gradient. Neither downloads pretrained weights or FineWeb, and their numbers are not scientific results.

## Tables and figures

```bash
python scripts/paper_tables.py --artifacts
python scripts/revision/pass1_tables.py --evidence bundle
python scripts/revision/tier2_correlations.py --evidence bundle
python -m pip install -r requirements/figures.txt
python scripts/paper_figures.py --artifacts paper/artifacts --out-dir outputs/figures
```

These commands regenerate part of the paper's tables, not all of them. Table numbers are those of the published paper.

| Command | Tables |
|---|---|
| `pass1_tables.py --evidence bundle` | Table 3 (main quantization table): every row as printed, in `tex/ladder_body.tex`. The grid cells shown in Table 4 (KIVI-style grid) and Table 9 (locality boundary), in `pass1_tables.md`. Also the single-tensor grid and the best-configuration audits cited in the text |
| `paper_tables.py --artifacts` | The values of Table 2 (paired differences; five of its seven rows), Table 4, Table 5 (dose-response), and Table 10 (quantizer-side controls). It is the generator of the first version of the paper: labels, columns, and number formatting differ from the published tables, and its four-condition version of Table 3 is superseded by the row above |
| `tier2_correlations.py --evidence bundle` | Table 12 (median layer-wise correlations). The correlations are recomputed from the layer-wise records and compared with the registered values in `paper/artifacts/analysis/` |
| `paper_figures.py` | The three data figures |

Not regenerated by a command in this repository: Tables 6 and 7 (zero-shot results), Table 8 (LoRA-scale probe), and Table 13 (fixed-Q attention). Their result files are in `paper/artifacts/zeroshot/`, `paper/artifacts/probes/lora_kv/`, and `paper/artifacts/kv_quant/attention/`. Tables 1, 11, and 14 summarize or index results and carry no measured values of their own.

The two `--evidence bundle` commands first verify every file of `paper/artifacts/` against the manifest, write to `outputs/revision/analysis_bundle/`, and record in their output that the raw measurement chain was not replayed. None of the commands reruns a model.

Generated files should go under `outputs/`, not into `paper/artifacts/`. Do not edit a manifested result file.

## Result files: sanitization and binding

`paper/artifacts/` contains sanitized copies of result files, not the original raw byte stream. Private path and repository identity fields were projected into a public representation, including nested JSON payloads. The manifest binds these **sanitized bytes**. Digest fields inside the result files can describe historical raw inputs; they are retained as historical evidence and do not imply that those raw inputs ship here.

Regenerating a table from these files therefore does not establish raw-chain replay, possession of model weights, or independent remeasurement.

## Original runs

`pass1_tables.py` and `tier2_correlations.py` in their default mode (`--evidence full`) read the original output tree, and the registered launch drivers authenticate raw files, checkpoint digests, package freezes, output isolation, launch manifests, and code identities that are deliberately absent here. They are expected to refuse on this checkout alone. A fresh public Git history is not the original history. Do not disable those guards and describe the resulting run as an authenticated replay of the paper.

To make an independent experimental rerun possible, the checkpoint binaries and the remaining raw dependencies must first be made available, with a documented way to reconstruct the relevant input layout. New runs also require dataset/tokenizer access and suitable GPU capacity. See [Experiment entry points](EXPERIMENTS.md).
